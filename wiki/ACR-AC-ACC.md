# AC / ACC / AC Rally（共享内存）

这三款游戏把物理遥测写入 Windows 命名共享内存 `acpmf_physics`。
Proton/Wine 进程在独立命名空间里，原生 Linux 程序读不到，所以需要**同前缀内的桥**。

```
acr.exe (Proton) ──写──► acpmf_physics
                              ▲
ds5bridge.exe (同前缀) ──读────┘ ──UDP 127.0.0.1:9999──► ds5d ──► 手柄
```

## 两段式启停（推荐）

由于 Proton 容器机制，如果在游戏启动前就通过 `protontricks` 拉起桥，会导致 Proton 前缀被提前锁定，进而导致 Steam 无法正常拉起游戏。因此采用**两段式启动**：

```bash
# 第 1 步：启动 Linux 原生触感守护进程（加载 assetto-corsa profile 并接管手柄）
./scripts/ds5-acr.sh start

# 第 2 步：打开 Steam 正常启动 Assetto Corsa Rally (ACR) 并进入赛道

# 第 3 步：游戏运行后，在终端一键注入共享内存桥
./scripts/ds5-acr.sh bridge

# 或者直接使用全自动侦测模式（启动 ds5d 并在后台自动等待游戏启动后注入桥）：
./scripts/ds5-acr.sh auto
```

常用命令：
```bash
./scripts/ds5-acr.sh status          # 查看进程状态、游戏运行状态与当前信号
./scripts/ds5-acr.sh stop            # 干净停止全部服务并释放手柄
./scripts/ds5-acr.sh logs            # 同时实时查看 ds5d 与桥的追踪日志
```

AppID：AC `244210` · ACC `805550` · AC Rally `3917090`

## 手动等价

```bash
make bridge
./bin/ds5d -profile assetto-corsa -rate 125 &
./scripts/launch-bridge.sh 3917090
```

## 何时才算通

- 桥日志出现 `opened "acpmf_physics"; streaming`
- `ds5d -trace` 出现 `signals: brake=... accel_g=... speed=...`

**只在进入赛道后**共享内存才存在；菜单里桥会一直打印
`shared memory not found — retrying`，这是正常的。

## 实测信号量级（ACR）

| 场景 | `accel_g` 绝对值（G） |
|---|---|
| 平稳巡航 | 0.00 – 0.05 |
| 砂石 / 颠簸 | 0.05 – 0.20 |
| 路肩 | 0.40 – 1.9 |
| 撞击 | 2.0 – 4.3（记录到过 13.17） |

Profile 里的阈值都按这个标定。

注意 `wheelSlip` 是**原始滑移量**（实测可到 8），不是 0..1。直接写 `slip > 0.5`
会让左马达长期饱和；应做归一化，例如
`clamp(230 * smoothstep(0.35, 2.5, slip), 0, 230)`。

## 常见坑

- **桥在游戏重启后卡死**：日志不再增长但进程还在 → 重新执行 `./scripts/ds5-acr.sh bridge` 注入或通过 `./scripts/ds5-acr.sh restart` 重启
- **`surface` / `carDamage` 在 ACR 恒为 0**：这两类字段该作无实现，规则会静默失效
- **Steam Input 必须开着**（ACR 只认虚拟 Xbox 手柄），但我们的触感走 hidraw，不受影响
